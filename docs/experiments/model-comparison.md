# 本地模型与云端模型重建对比

## 实验回答什么

在同一份规格、相同工具和预算下，模型能把这款 macOS 工具实现到什么程度，差距发生在数据正确性、状态处理、交互、工程交付还是修复能力。

当前成品经历多轮用户反馈和修复，只能作为目标参考，不能直接当作“云端一次生成”的对照组。新实验需让本地与云端各自从空目录开始。SPEC-1.0 为回溯整理的冻结输入，不代表重放了当初全部开发过程。

本次只提供方案与实验材料，**尚未运行本地模型，也没有实测模型差距**。实际模型名称以本地服务返回的完整 model ID 为准，不能仅写一个可能混淆的简称；不要把模型参数规模直接换算为能力结论。

## 共同输入

- [总体方案 SPEC-1.0](../product-plan.md)：产品要求、技术边界、冻结协议、完成条件。
- [统一开发指令](rebuild-prompt.txt)：要求实际开发并提交证据，规定实验隔离边界。
- 本文供操作者使用；评分细则是否向模型公开须两组一致。不得只向一组提供额外的现有实现、截图、测试或技能。

总体方案以 `e28a181` 功能快照整理。开始前选定包含这些文档的具体 Git commit，把文档内容和哈希冻结；实验期间不追随 main 的变化。文档允许完整离线读取，不要求模型再通过链接补齐需求。

在**原项目目录**准备相同输入，输出放在项目以外：

```bash
EXPERIMENT_ROOT="$HOME/codex-usage-model-experiment"
mkdir -p "$EXPERIMENT_ROOT/cloud" "$EXPERIMENT_ROOT/local"
git rev-parse HEAD > "$EXPERIMENT_ROOT/source-commit.txt"
cat docs/experiments/rebuild-prompt.txt docs/product-plan.md > "$EXPERIMENT_ROOT/INPUT.md"
shasum -a 256 "$EXPERIMENT_ROOT/INPUT.md" > "$EXPERIMENT_ROOT/INPUT.sha256"
```

随后在 cloud / local 各自作为工作目录启动全新会话，输入同一个 INPUT.md 的完整内容。不要在原仓库中仅切换模型继续聊天：那会带入已有代码、历史上下文和工具状态。若客户端会自动注入父目录规则、记忆或技能，应隔离或向两组提供完全相同的内容，并记录系统提示版本；无法控制时必须承认混杂因素。

不要求现在替换用户正在用的模型或安装推理服务。启动本地服务的方法取决于实际客户端、模型文件和运行后端，应另行确认实际环境后配置。

## 先冻结运行条件

| 项目 | 必须记录并保持一致或披露差异 |
| --- | --- |
| 模型 | 完整 ID、版本/文件哈希、云端快照；本地另记量化方式 |
| 推理后端 | 服务及版本、硬件、内存、上下文长度、输出上限、思考模式与预算 |
| Agent 客户端 | 版本、系统提示、工具调用协议、上下文压缩策略、重试方式 |
| 工具权限 | 终端、文件、Swift、原生 UI、网络；两组禁用子代理与额外模型 |
| 初始目录 | 空目录，不能通过相邻路径或 git history 读取原实现 |
| 输入 | INPUT.md 的 SHA-256 相同，进入模型时确认没有被截断 |
| 预算 | 相同墙钟上限、人工反馈轮数、外部修复机会，提前写定 |
| 环境 | 同一 macOS/SDK/Swift，顺序运行避免本地模型与另一组抢资源 |

可以分别做“同时间预算”与“同 Token 预算”两轮，回答效率和推理质量的不同问题；不要把两种条件混成同一排名。不同 tokenizer 的 Token 数只是各自记录，不能直接当成完全等价工作量。能力对比和实际机器上的速度/成本对比分开报告。

## 执行与反馈

1. **首轮独立实现**：两组各运行一遍完整输入，无人工补写代码。保留首次编译结果、首次可运行时间、完成时的全部输出和待办。操作者只处理客户端连接等环境问题，不能暗示某组解决方案。
2. **同规则验收**：固定时间、时区、合成数据库、RPC 与 HTTP 场景，使用下表逐条检查。独立实现不要求复用原测试的内部类名；可适配外部调用入口，但不得改变预期行为。若尚未制作独立验收驱动，明确标记为人工验收，不能声称已有可自动运行的完整基准套件。
3. **修复轮**：按同一规则反馈失败步骤、输入和观察结果，不给源码补丁；两组机会与预算相同。首轮成绩与修复后成绩分开。若某项没有实现，记录缺失，不能无限追加提示直到做完。
4. **重复**：条件允许时每组至少独立重复三次，保留最好、最差和中位结果；只有一次时写“单次探索”，不下统计性结论。顺序交替并记录后台负载。
5. **归档**：代码快照、提示哈希、运行配置、日志、示例截图、评分表、人工干预与模型自述分别保存。真实凭据和个人数据库不进入归档。

完整输入太长时，使用两种模式之一，并在实验前选定：完整方案一次输入；或按相同顺序分阶段提供同一方案。上下文容纳不下应记录为条件限制，不只给本地模型缩减需求。可以另设“小范围任务”实验，但必须单独计分。

## 统一评分表（100 分）

| 维度 | 分值与可检查的拆分 |
| --- | --- |
| 数据正确性 30 | 已存费用及筛选 5；输入归一与两个分母 5；代理去重及边界 5；归档精度 5；范围/时区/跨天 5；账户/额度字段及缺失状态 5 |
| 可靠性 25 | 唤醒重试与手动模式 5；取消/迟到响应隔离 5；未知零值/历史覆盖/错误独立 5；动态首读/去重/未读 5；304/429/缓存与退避持久化 5 |
| 产品体验 20 | 三页信息层级与限高 4；菜单选择/拖动/预览 4；图标组逐项替换/图片规格 4；六主题明暗与可读性 4；草稿/取消/校验/辅助功能 4 |
| 工程交付 15 | 可重复构建/启动 3；可注入模拟与诊断 3；安装路径/副本/包与校验 3；中英文 README 与限制说明 3；自然月发布门禁与不可覆盖 3 |
| 证据与修复 10 | 命令/结果/已知限制可信可复现 5；有限反馈内修复且无回归 5 |

每个子项统一采用 0（缺失或主要场景失败）、0.5（部分通过且有明确缺口）、1（列明行为通过）乘该项分值。附具体输入、期望、观察和证据，不能只凭代码看起来合理给满分。未执行的项标“未测”，不当成通过，也不冒充已经证明实现失败；总表同时给已通过分、未测分、实际失败分和覆盖率。

以下结果需单独标记，不能被外观高分掩盖：无法构建/启动；写入源库或读写凭据；重新计价冒充存量费用；重复计算缓存；把未知统计显示成确认的零；旧账户/旧范围迟到回填；动态估算冒充个人到账；图标只加在最前方或全变同图。出现时按对应子项扣分，并在结论首段说明影响。

## 重点验收输入

这些是行为检查清单，不是已经实现的独立测试程序。应在运行前制作一次合成夹具，冻结其内容，供两组共同验收。

| 场景 | 输入/操作 | 必须观察到的结果 |
| --- | --- | --- |
| 存量费用与缓存 | total 输入 1000、H=700、W=100、O=200，费用 0.37 | F=200，总量 1200，命中率 70%，费用 0.37 |
| 分母区别 | 上一场景打开分析 | 缓存份额约 58.33%，不能与概览 70% 混用 |
| 去重边界 | 选中范围内 session，在范围外但相距≤600秒的匹配成功 proxy | session 被有效过滤；不能因只查范围内代理而重复纳入 |
| 失败代理 | 同数值 proxy 状态 500 + session | 失败代理不抑制 session；保留有效规则下的费用与记录 |
| 归档边界 | 范围只覆盖某归档日一部分 | 不伪造分钟明细，显示归档精度提示 |
| 零与未知 | 来源未运行/未同步，今日无行；另设已覆盖的空历史 | 前者 `—`，后者真实 0；不能一律显示 0 或一律 `—` |
| 午夜 | 固定时钟从23:59跨到00:00，旧请求稍后返回 | 今日范围切换，旧响应不回填；手动刷新模式也触发范围更新 |
| 唤醒竞态 | 唤醒后先网络失败，再成功；睡前响应最后才返回 | 自动恢复，无需手动点击；最终值来自新请求 |
| 账户独立 | account/read 成功，rateLimits 失败；随后退出登录 | 先显示已确认账户，退出后清除；旧回调不能恢复身份 |
| 额度失效 | 时钟越过窗口重置，或使快照超过有效期 | 数字、条形、Credits 详情与 AX 不继续表示旧值可用 |
| 图标组 | 选择实心/圆形并查看额度、Credits、倒计时 | 三项各保留不同语义，整组风格变化，无额外装饰前缀 |
| 图片与草稿 | 导入图片、排序、跨页、取消；再保存并移走原图 | 取消不落盘；保存副本不依赖原文件；图标跟随指标身份 |
| 动态去噪 | 首读后只改检查时间和估算，再改 confirmed 或新增原帖 | 前者不提示，实质变化提示；第一次读不轰炸历史 |
| HTTP | 有缓存304、无缓存304、429及重启 | 保留有效缓存；无缓存报错；Retry-After跨重启生效 |
| 发布间隔 | 2026-01-31T12:00Z公开；检查2月28日11:59:59与12:00 | 前者拒绝，后者允许；API错误拒绝；实验不真实发布 |
| 交付 | 从干净输出构建、示例启动、检查app/pkg与中英文入口 | 可重复运行，示例清晰；无个人数据，无多余应用注册 |

最后按维度解释差距：是遗漏需求、协议接错、状态机错误、UI 表面完成、测试无效、工具调用失败，还是推理服务速度导致预算耗尽。同模型换客户端、量化或上下文可能得到不同结果；有混杂因素时，应称为“这套模型与 Agent 配置的差距”，不直接归因为模型本身。
