## 0.3.3 唤醒恢复与账户显示

原逻辑只监听系统 `didWake` 并立即请求一次；网络恢复尚未完成或旧查询在途时，会失败、清空额度，再等待常规定时刷新。现在同时监听系统唤醒、屏幕恢复和会话重新激活；休眠时取消在途任务，唤醒分配新请求标识，过期结果不更新状态。通知短时间去重，失败后使用 2、5、10、20、30、60 秒间隔重试，网络可用事件可提前触发恢复。此流程不依赖用户的自动刷新间隔。

账户使用 `account/read` 已有响应中的类型、邮箱和套餐。账户先独立发布，额度接口失败不隐藏已确认身份；未经核对时明确显示“上次识别账户”。配置切换与退出登录清理旧身份，成功快照与迟到回调顺序均有回归覆盖。不读取认证文件，不保存账户显示信息到磁盘，不发起应用内登录。

2026-10-16 09:01：安装版 `--diagnose-wake` 返回 `quotaAvailable`、`statisticsAvailable`、`accountVerified`、`accountDetected`、`hasEmail`、`recoveryFinished` 均为 true，认证类型为 chatgpt；命令不打印邮箱、账户 ID 或凭据。该诊断使用真实 Codex RPC 与数据库，但只模拟模型层的唤醒，不使系统休眠。

已从 Finder 启动 0.3.3 安装版，未点击刷新即观察到账户卡片先显示邮箱与 PRO，随后额度完成为每周剩余 69%、Credits 62,197.23，以及今日 $47.92、244.21M Tokens、1,100 次请求、96.1% 缓存命中率。数值为核对时快照。原生示例预览检查账户卡片布局，账户邮箱可选中复制。

没有主动让用户机器休眠或断网。自动化使用受控失败、在途旧响应及网络恢复事件覆盖竞态；真实硬件休眠后的最终体验仍需后续观察。数据扩展审计及覆盖边界见 [数据源分析](data-sources.md)。
