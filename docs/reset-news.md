# AIHOT 重置动态集成

版本 0.3.0，2026-10-15 实现并验证。

## 来源与接口

- 来源页面：[Tibo 重置监控](https://aihot.news/codex-reset)。
- 接口定义：[AIHOT OpenAPI v1](https://aihot.news/openapi-v1.json)。
- 轮询端点：`GET https://aihot.news/api/v1/codex-resets/recent`，匿名只读，不携带 Codex 登录凭据或账户信息。
- 使用 `User-Agent: aihot-api/2.0.0 CodexUsage/0.3.0`、gzip 和 `If-None-Match`；遵守 304 与 `Retry-After`。
- 最短间隔 600 秒，检查时间和限流退避跨进程重启保存。使用最近快照，不轮询完整历史。

原生 URLSession 已成功读取线上 JSON：4 条近期事件，监控健康，无待生效预告，首次读取未产生未读历史提示。实际记录随网站更新，本结果只是验证时快照。

## 展示语义

- 使用 `displayLabel`，不展示旧兼容字段 `label` 中可能夸大范围的“全员重置”。
- `presentation.scopeKnown = false` 明确展示“原帖未说明适用人群”。已说明时优先展示中文适用人群和附带条件，产品范围单独显示。
- `source_post` 与 `receipt_review` 分别标记“Tibo 已确认”和“到账核实”。
- 未确认、进行中、预计窗口已过及可能生效保持待确认语义；不将时钟走过预计窗口视为到账。
- 预计窗口标记为“AIHOT 预计”，已确认记录不继续展示旧预计窗口。
- 时间全部格式化为北京时间。确认时间是确认帖／核实记录时间，不冒充账户实际执行时刻。
- 仅打开 AIHOT、X 或 Twitter 的 HTTPS 来源链接；不执行外部正文，也不嵌入网页脚本。应用只展示事件摘要字段及原帖链接，不复制完整帖子。

## 未读与缓存

`ResetNewsInbox` 将当前事件语义版本及来源帖子 ID 保存为基线。第一次成功读取即使为空也完成初始化；后续新增事件、状态确认、实质更正或新增来源帖成为未读。同一事件的多项变化合并为一个未读项。

语义版本排除检查时间、`updatedAt` 的单纯变化、AIHOT 动态估计窗口与推算状态。帖子从最近时间窗中自然移出不产生新提醒。只有 `event_update + statusChanged + action=withdraw` 作为明确撤回处理，普通社交互动不触发提示。

每次以新快照替换旧快照，删除不再存在的未读引用，避免悬空提示。304 保留缓存和已读状态。请求失败也保留缓存与未读状态；不以错误页面替换内容。

提示开关仅控制菜单栏铃铛，不抹除未读记录。暂停获取会停止后台请求并隐藏图标提示。打开下拉面板时，如存在提示，默认进入动态页；动态页实际可见后标记已读。面板已关闭而保留动态页选择时，不会把后台新消息误标为已读。

## 验证

核心测试覆盖首读基线、空基线后首条消息、确认更新、新原帖、明确撤回、普通互动去噪、估计变化去噪、时间窗滚动、已读与缓存持久化、304、429、网络失败、协议变更及链接限制。

使用隔离 QA 偏好和模拟未读缓存验证原生 UI：铃铛提示、开关预览、点击后进入动态页、查看后未读清零，以及切换回用量页。未改写生产偏好中的显示项或已读状态。线上读取与模拟未读 UI 测试分别进行，未声称网站在测试期间发布了新公告。
